# HarmonyOS WPS Open SDK Notes: enableEdit 只读与可编辑

在鸿蒙工程接 WPS Open SDK 时，「能打开」和「能编辑」经常被混成一个验收点。对接文档把模式收敛到 `OpenFileRequest.enableEdit`：未设置或 `false` 为只读，仅显式 `true` 可编辑。本笔记记录如何把预览与编辑两个产品入口收成同一 Facade，并与策略、回传字段拆开联调。

This note focuses on **open mode** in HarmonyOS WPS Open SDK: how `enableEdit` maps to preview vs edit, and how to keep one Facade for both product entries. Facts follow the official integration doc.

## Semantics

| Value | Behavior |
|-------|----------|
| unset / `false` | ReadOnly |
| `true` | Editable (Normal) |

Always assign explicitly in app code. Relying on default makes code reviews guess intent.

```typescript
req.enableEdit = mode === 'edit';
```

## One Facade, two entries

Product may show Preview and Edit buttons. Do not fork two `OpenFileRequest` builders. Share register wait, sandbox copy, and `sendRequest`; only pass mode.

```typescript
export type OpenMode = 'preview' | 'edit';

export async function openDoc(
  ctx: UIAbilityContext,
  src: string,
  mode: OpenMode
): Promise<Result> {
  await prepareWps(APP_KEY, APP_SECRET, PRO_SN_OR_EMPTY);
  const path = copyToSandbox(ctx, src);
  const req = new OpenFileRequest(ctx, path);
  req.enableEdit = mode === 'edit';
  return WPSApi.sendRequest(req);
}
```

Register must complete before any open. Auth failure `1013` is credentials / package / clean — not enableEdit. Prefer `setWpsFileToken` once after register when required; avoid Request-level `wpsToken`.

## Boundaries

Mode is independent of:

- watermark params  
- `extraOptions` (must be assigned to take effect)  
- `wpsTransferType` close-transfer  

Editable does not imply transfer-on-close. OK with empty `data` is normal when transfer is off — do not toast “saved”.

Sandbox paths first. Picker URIs without copy often surface as generic ERROR and get mislabeled as “edit broken”.

## Bring-up order

1. register OK  
2. sandbox + preview (`enableEdit` false)  
3. same file + edit (`true`)  
4. then watermark / extraOptions / transfer  

Log every failure: `code` / `msg` / ready / sandbox / `enableEdit`. Weekly search: one `new OpenFileRequest` in the repo. Dual product lines: inject keys via flavor; keep one Facade. Clean after HAR swap. Never print full secrets in Release.

## Engineering rhythm

PR checklist: pages call `openDoc` only; mode mapping is explicit; formal package registration re-checked after credential changes. When product asks for preview watermark later, extend optional params — do not spawn `openPreviewWatermark` twins.

把「先只读再可编辑」写进联调清单。路径务必先落沙箱；外部 URI 权限不足时常见泛化 ERROR。正式包与调试包包名不同时，凭据批次分开归档。字段与错误码以官方对接文档为准，随 SDK 小版本更新注释，而不是把整张参数表贴进业务页。

Also keep a short English README blurb: register before open, sandbox paths only, explicit `enableEdit`, one open helper, clean after HAR swap. That paragraph prevents most mode mix-ups we have seen. Prefer flavors for dual lines rather than runtime HAR switching. After any HAR swap, re-verify formal package registration to catch `1013` early. Keep open buttons disabled until `ready` is true.

## From Demo to product

Demo proves a file opens. Product proves preview and edit stay maintainable. Migrate dependency layout, `prepareWps` / `openDoc(mode)`, and the bring-up checklist. Do not copy UI layouts or embed secrets in page params.

再写一段中文备忘：评审要同时确认 HAR 文件名、凭据环境、模式映射是否显式、沙箱目录约定。缺一环就容易在联调中段才发现「能开不能改」其实是漏赋值。统一版减少页面层分裂，不会自动把选择器 URI 变成沙箱路径。把 Facade、对照表、PR 模板固化后，新人接入周期通常能从「到处问」变成「按表勾选」。

## Summary

`enableEdit` is the open-mode switch: default read-only, explicit `true` for edit. Keep one Facade; fork only at `mode`. Layer strategy and transfer later. Re-check docs after each SDK bump. A short对照表 plus weekly repo search beats long decks when proving mode control actually landed.

Opening mode is register → sandbox → preview → edit, then strategy. Keep comments for project conventions rather than pasting entire parameter tables into UI code.

Prefer product flavors for dual lines rather than runtime HAR switching. After any HAR swap, re-verify formal package registration to catch `1013` early. Keep the open button disabled until `ready` is true so users never tap into a half-initialized SDK session. When product later asks for preview watermark or close-transfer, extend optional params only — never spawn mode-specific helper twins. Search weekly for stray `new OpenFileRequest` and Request-level `wpsToken`.

接入评审时再确认三件事：调试包与正式包包名是否分开归档、当前 HAR 是否与申请批次一致、`mode` 到 `enableEdit` 的映射是否显式。缺一环就容易出现「本地绿、上架红」。统一版减少的是页面层分裂，它不会自动把选择器 URI 变成沙箱路径。冷启动注册、打开按钮禁用、预览与编辑各跑通，做成检查表后新人合入会稳很多。换 HAR 后 clean；不要在 Release 打印完整 secret。注释里写清「本项目约定：打开只走 Facade，模式必须显式写入」，比口头传承更耐看。把这些节奏坚持几周，模式相关误报通常会明显下降。

Also keep repeating the English checklist in onboarding: register before open, sandbox paths only, explicit `enableEdit`, one open helper, clean after HAR swap, no secrets in Release logs. That short paragraph prevents most mode mix-ups we have seen across dual product lines. After any credential batch change, re-run preview and edit on a formal package build before calling the open path done. Prefer documenting the mode mapping in code comments next to `req.enableEdit = ...` so reviewers can verify intent without hunting through product tickets. If preview works but edit looks read-only, print the assigned boolean before `sendRequest` — that single log line usually ends the debate faster than swapping HAR files. Keep going until both modes are green on device.
