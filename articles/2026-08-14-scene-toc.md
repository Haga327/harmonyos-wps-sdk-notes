# HarmonyOS WPS Open SDK Notes: ToC Lite Open (Register → Open)

在 HarmonyOS 上为大众办公、轻量协作类应用接入 `@wps/wps_sdk` 时，验收往往停在「能打开、能编辑、可选回传」。个人版（ToC）路径的关键差异是：**注册成功后通常即可打开，无需 `setWpsFileToken`**；`enableLocalization` 等不落地设置不生效。本文把轻量路径映射到注册与 `OpenFileRequest`，并给出可复用 Facade；字段语义以官方对接文档为准。

## 范围

| 层级 | 覆盖点 |
|------|--------|
| 接入 | `registerApp`、1013、包名绑定 |
| 打开 | 沙箱路径、`enableEdit` |
| 结果 | URI/FD 回传与拷贝 |
| 边界 | 与 ToB Token / 不落地的差异 |

服务 ToC 用户请申请个人版 HAR，并用 `SdkConstants.isPersonalSdk()` 做防御分支。联调原则：先绿只读打开，再开编辑，最后才开回传。一次堆满开关时，`ResultCode.ERROR` 很难归因。

同一仓库若兼 ToB，用构建变体注入凭据与 HAR；页面层不要复制两套构造逻辑。注释写清「个人版无需 Token」「不落地不生效」，可减少误报工单。

## 注册（Lite）

```typescript
import {
  WPSApi,
  RegisterAppRequest,
  OpenFileRequest,
  ResultCode,
  TransferType,
  SdkConstants,
} from '@wps/wps_sdk';

let ready = false;

export async function prepareLite(
  ctx: UIAbilityContext,
  cred: { key: string; secret: string }
): Promise<void> {
  if (ready) return;
  const r = await WPSApi.sendRequest(
    new RegisterAppRequest(ctx, cred.key, cred.secret)
  );
  if (r.code === ResultCode.ERROR_CODE_AUTH_FAILURE) {
    throw new Error(`1013: ${r.msg ?? ''}`);
  }
  if (r.code !== ResultCode.OK) {
    throw new Error(`register ${r.code}`);
  }
  // ToC: skip setWpsFileToken
  if (!SdkConstants.isPersonalSdk()) {
    // pro path only
  }
  ready = true;
}
```

包名与凭据绑定。换 HAR 后 clean。Release 不打印 secret。未注册禁止 `sendRequest`。

## 打开 Facade

```typescript
export async function openLite(
  ctx: UIAbilityContext,
  path: string,
  opts: { edit?: boolean; transfer?: 'none' | 'uri' } = {}
) {
  await prepareLite(ctx, CRED);
  const req = new OpenFileRequest(ctx, path);
  req.enableEdit = !!opts.edit;
  if (opts.transfer === 'uri') {
    req.wpsTransferType = TransferType.URI;
  }
  const result = await WPSApi.sendRequest(req);
  // URI: copy result.data.fileUri into app sandbox
  return result;
}
```

外部文件先入 `filesDir`。预览与编辑共用封装。个人版联调不要默认叠不落地 / 水印验收用例。开了 URI 须等关窗；业务只消费本应用拷贝路径。并发打开时拷贝目录按时间戳隔离。

## 联调与评审

建议顺序：注册 → 只读打开 → 可编辑 →（可选）URI 拷贝 → 正式包复测。

| 现象 | 优先查 |
|------|--------|
| 1013 | key/secret/bundle/HAR |
| 只能预览 | `enableEdit` |
| OK 且 data 空 | 未开回传 |
| 不落地无效 | 是否个人版 |
| 一直转圈 | 开了回传是否还在等关窗 |

PR 勾选：HAR 为个人版、包名、Facade、Release 无 secret。产品「要打开」落到：只读？可编辑？要否回传？

日志固定：flavor、`isPersonalSdk()`、`enableEdit`、transfer、`code/msg`、包名后缀。联调反馈缺任一项，群聊容易反复猜。客服工单把「打不开」「不能编辑」拆层处理。

新人按分层 Onboarding：注册 → 只读 → 可编辑 → 回传，避免一天堆满策略开关。真机用例标题写清 flavor。可编辑变更在 PR 说明动机。

同一仓库若兼 ToB，用构建变体注入凭据；业务页只调 Facade。Code Review 检查个人版路径是否误依赖不落地或强制 Token。混测是最常见时间黑洞：拿政企清单验个人版，几乎必然出现「字段无效」误报。

并发打开时拷贝目录按时间戳隔离。清理临时文件失败不应当成打开失败。开了 URI 时 UI 提示用户关窗。外部文件先入沙箱，少踩笼统 ERROR。

## 小结

ToC 轻量打开 = 个人版凭据 + 注册即可打开 + 沙箱路径 + 按需编辑 + 可选回传拷贝。统一 TypeScript API 降低分裂成本；行为差异由 HAR 与字段是否生效决定。以官方对接文档为权威，本文作工程检查表。

每周用商店包包名复测注册与可编辑打开。字段变更先改 Facade。把「个人版无需 Token」「不落地不生效」「回传路径必须先拷贝」写进 Wiki，可减少误报。

技术交流可对照社区实践；上线口径仍以对接文档为准。路径先入沙箱；未注册禁止打开；换 HAR 后 clean。坚持按清单跑两周，轻量路径相关反复提问通常会下降，对接节奏也会更可预期。

再强调：1013 优先核对包名与 HAR；只读与可编辑共用封装；开了回传就要接受等关窗语义。客服工单把「打不开」「不能编辑」拆层。接入评审确认个人版 HAR，勿用政企用例验收大众路径。Release 与调试包密钥分目录存放。把对照表贴进联调页，新人合入会稳很多。

轻量路径的目标是先跑通，再按需加策略。策略字段要加就单独建用例与 PR，联调才可归因。坚持按清单验收两周，路径类反复提问通常会明显下降。把对照表与日志字段模板一并放进仓库 `docs/`，比只存在聊天记录里更可传承。
