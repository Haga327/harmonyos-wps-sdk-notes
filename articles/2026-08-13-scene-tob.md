# HarmonyOS WPS Open SDK Notes: ToB Compliance Open (Localization / Watermark)

在 HarmonyOS 上为政务、金融、企业协作类应用接入 `@wps/wps_sdk` 时，验收很少停在「能打开文档」。典型 ToB 要求还包括：专业版客户端与激活序列号、文档默认不在 WPS 侧持久化缓存（不落地）、打开页水印、分享/打印等入口可控，以及关窗后把结果拷回本应用沙箱。本文把这些要求映射到注册与 `OpenFileRequest` 字段，并给出可复用 Facade；字段语义以官方对接文档为准。

## 范围

| 层级 | 覆盖点 |
|------|--------|
| 接入 | `registerApp`、1013、包名绑定 |
| 授权 | `setWpsFileToken`（专业版） |
| 策略 | `enableLocalization`、水印、`extraOptions` |
| 结果 | URI/FD 回传与拷贝 |

ToC 个人版路径更轻，通常无需序列号，且 `enableLocalization` 设置不生效。服务政企客户请申请专业版 HAR，并用 `SdkConstants.isPersonalSdk()` 做防御分支。

联调原则：先绿「可编辑打开」，再叠不落地与水印，最后才开回传。一次堆满开关时，`ResultCode.ERROR` 很难归因。业务页只传策略对象，字段装配收在 Facade，便于 Code Review 与复测。

同一仓库若兼 ToC / ToB，用构建变体注入凭据与 HAR；页面层不要复制两套 `OpenFileRequest` 构造逻辑。注释写清「不落地时部分 extraOptions 会被强制关闭」，可减少误报工单。

## 注册与 Token

```typescript
import {
  WPSApi,
  RegisterAppRequest,
  OpenFileRequest,
  ResultCode,
  TransferType,
  SdkConstants,
} from '@wps/wps_sdk';

let ready = false;

export async function preparePro(
  ctx: UIAbilityContext,
  cred: { key: string; secret: string; sn?: string }
): Promise<void> {
  if (ready) return;
  const r = await WPSApi.sendRequest(
    new RegisterAppRequest(ctx, cred.key, cred.secret)
  );
  if (r.code === ResultCode.ERROR_CODE_AUTH_FAILURE) {
    throw new Error(`1013: ${r.msg ?? ''}`);
  }
  if (r.code !== ResultCode.OK) {
    throw new Error(`register ${r.code}`);
  }
  if (!SdkConstants.isPersonalSdk() && cred.sn) {
    WPSApi.setWpsFileToken(cred.sn);
  }
  ready = true;
}
```

未注册完成就 `sendRequest` 会 reject。勿在每次 `OpenFileRequest.wpsToken` 重复赋值。多环境包名分开申请凭据；密钥构建注入；换 HAR 后 clean。

## 不落地与强制关闭

| `enableLocalization` | 行为 |
|----------------------|------|
| 未设置 / `false` | 不落地（ToB 默认）；敏感能力强制关闭 |
| `true` | 允许落地；由 `extraOptions` 细控 |

强制关闭包括：云文档/登录/收藏、分享、历史版本、另存为/打印/导出 PDF、复制粘贴剪切、截图、自动上传等。联调「extraOptions 无效」时，先确认是否仍处于不落地模式。

不落地 + URI 回传：拷贝到本应用沙箱后，可删除 WPS 侧临时文件；删除失败只记日志。

## 策略 Facade

```typescript
export type CompliancePolicy = {
  watermark?: string;
  allowPersist?: boolean;
  transfer?: 'none' | 'uri' | 'fd';
};

export async function openCompliance(
  ctx: UIAbilityContext,
  sandboxPath: string,
  cred: { key: string; secret: string; sn?: string },
  policy: CompliancePolicy = {}
) {
  await preparePro(ctx, cred);
  const req = new OpenFileRequest(ctx, sandboxPath);
  req.enableEdit = true;
  if (policy.allowPersist) {
    req.enableLocalization = true;
  }
  if (policy.watermark) {
    req.wpsWaterMarkParams = {
      Enable: true,
      WaterMaskText: policy.watermark,
      Angle: -30,
    };
  }
  if (policy.transfer === 'uri') {
    req.wpsTransferType = TransferType.URI;
  } else if (policy.transfer === 'fd') {
    req.wpsTransferType = TransferType.FD;
  }
  try {
    return await WPSApi.sendRequest(req);
  } catch (e) {
    console.error('sendRequest rejected', e);
    throw e;
  }
}
```

页面只传 policy；预览用 `transfer: 'none'`。水印文案集中配置。全仓保持单一打开入口。

## 联调与评审

建议顺序：注册+Token → 无策略可编辑打开 → 确认默认不落地 → 水印 →（可选）可落地+extraOptions → URI 拷贝 → 正式包复测。

| 现象 | 优先查 |
|------|--------|
| 1013 | key/secret/bundle/HAR |
| 菜单关不掉 | 不落地强制关闭 |
| 只能预览 | `enableEdit` |
| OK 且 data 空 | 未开回传 |
| 水印缺失 | 是否写入同一次请求 |

PR 勾选：HAR 版本、包名、Facade、不落地默认是否被误改、Release 无 secret 日志。产品「要安全」落到：不落地？水印文案？关哪些菜单？要否回传？

日志固定：flavor、Token 是否已设、`enableLocalization`、水印开关、transfer、`code/msg`、包名后缀。联调反馈缺任一项，群聊容易反复猜。客服工单把「打不开」「不能编辑」「菜单关不掉」拆层处理。

同一仓库若兼 ToC，用构建变体注入凭据；业务页只调 Facade。Code Review 检查个人版路径是否误依赖不落地。新人按分层 Onboarding：注册 → 可编辑 → 不落地确认 → 水印 → 回传，避免一天堆满合规开关。

真机用例标题写清 flavor 与是否不落地。可落地变更必须在 PR 说明动机与 extraOptions 同步策略。并发打开时拷贝目录按时间戳隔离。

## 小结

ToB 合规打开 = 专业版凭据与 Token + 不落地默认 + 水印/菜单策略 + 回传拷贝。统一 TypeScript API 降低分裂成本；行为差异由 HAR 与字段是否生效决定。以官方对接文档为权威，本文作工程检查表。

每周用商店包包名复测注册与不落地可编辑打开。字段变更先改 Facade。把「不落地时部分开关强制关闭」「回传路径必须先拷贝」写进 Wiki，可减少误报。

技术交流可对照社区实践；上线口径仍以对接文档为准。路径先入沙箱；未注册禁止打开；换 HAR 后 clean。坚持按清单跑两周，策略相关反复提问通常会下降，对接节奏也会更可预期。
